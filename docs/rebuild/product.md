# Продукт Maffinet: решение P00

Дата: 4 октября 2026 года. Это согласованный рабочий scope переработки,
а не описание уже выпущенных функций. Реализация начинается с P01.

## Основной путь

Пользователь выбирает установленные приложения, нажимает «Включить» и
подтверждает системное разрешение VPN. Затем открывает выбранное приложение.
Maffinet автоматически применяет доступные локальные методы и показывает
факты о соединениях. Добавление нового пакета не требует нового переключателя
сервиса, записи в каталоге или знания DNS/Hosts/argv.

Первый экран: список выбранных приложений, одно действие сеанса, краткое
состояние. Выбор приложений, наблюдения и настройки имеют самостоятельную
навигацию. Детали движков доступны в инструментах. Пустой выбор не позволяет
запустить TUN; удаление последнего приложения останавливает сеанс.
Пакет Maffinet исключён. Изменение списка во время работы создаёт новую
ревизию и короткое объяснимое переподключение.

Основной режим: один VpnService, Kotlin supervisor, source-built transport,
прямой adapter к ByeDPI, broker видимого DNS и ограниченный AccessPlanner.
Нет root, регистрации, собственного сервера и обязательного VPN-провайдера.

## Что означают состояния

| Уровень | Пример текста | Доказательство |
|---|---|---|
| Сеанс | «Включено», «Переподключаемся», «Остановлено» | Реальное состояние TUN и ресурсов supervisor |
| Приложение без наблюдений | «Ожидаем трафик» | Нет доступных flow events; запуск engine не меняет этот статус |
| Восстановление | «Настраиваем доступ» | Активная bounded операция; указан срок и возможность остановить |
| Соединения | «Наблюдаемые соединения проходят» | Свежие двусторонние события данного UID/generation; не только sent bytes |
| Ошибка | «Есть ошибки подключения» | Причина DNS/transport, время, scope, действие retry |
| Ограниченная видимость | «Недостаточно данных» | Unknown/shared UID, скрытый DNS или hostname, истёкшее evidence |
| Проверенный сценарий | «Лента проверена пользователем» | Устройство, сеть, версия, сценарий, автор и дата явной проверки |

У проб DNS/TCP/TLS/HTTP/UDP свои результаты. HTTP200 главной страницы не
превращается в успешную проверку API, авторизации или медиа. Для shared UID
показывается группа пакетов; API26–28 допускает только общую сводку выбранного
набора. DNS→IP и outer SNI не дают точного имени конкретного flow.

## MVP и расширения

MVP включает явный app picker, собственный shell и миграцию, session lifecycle,
dual-stack TCP/UDP forwarding, видимый DNS UDP/TCP, короткий подбор допустимого
локального DPI на наблюдаемом сбое, память метода на данную сеть, STOP/revoke,
диагностику без payload и честные статусы. Собственный DoH и coherency mapping
входят после broker в P06; QUIC/ECH/NAT64 проходят отдельную приёмку P07.

Экспертные пользовательские команды, доменные фильтры и DNS сохраняются при
миграции с отчётом. Прежний hosts import означал список имён; IP mapping
включается отдельной политикой, старый файл не меняет смысл молча.

Telegram — независимый дополнительный инструмент, с отдельными desired/runtime
state, настройками, секретом и воспроизводимой сборкой. Выбор пакета Telegram
не включает MTProto автоматически. Ссылка подключения требует действия в
чужом приложении; секрет остаётся локальным и не попадает в отчёты.

Поздние расширения: версионированные hints известных endpoints, экспорт
обезличенной диагностики по действию пользователя, отдельный fake-IP прототип.
Room, множество Gradle-модулей, WireGuard/firewall и ML не нужны для MVP сами
по себе. Нет фонового перебора сайтов и массового опроса DNS-провайдеров.

## Границы обещания

Локальный DPI не меняет внешний IP. IP/GeoIP-блокировка и ограничения аккаунта
могут остаться. Smart DNS с proxy провайдера использует его внешнюю
инфраструктуру; такая политика требует явного разрешения. Предпочтение private
или split DNS не обходится автоматически. App-owned DoH/DoT/DoQ и системный
Private DNS могут скрыть имена: это ограничение видимости.

Не отключать ECH/сертификаты, не устанавливать CA/MITM и не replay application
data/POST/0-RTT. Общий запрет UDP443 и подавление AAAA не являются fallback.
Системный lockdown может блокировать невыбранные приложения: MVP его не
включает и не обещает независимость от этой внешней настройки. Always-on
поддержка объявляется только после lifecycle acceptance.

## Самостоятельность и приёмка

Новый application layer, экраны, тексты, data/repositories, supervisor и
policy создаются заново с собственной организацией. Изучение старого кода
уже состоялось; clean-room не заявляется. Для каждой переносимой реализации
фиксируются источник, лицензия и мотив. [Usage map](usage-map.md) задаёт этапы
удаления legacy. LICENSE/NOTICE и attribution остаются для сохраняемого кода.

Завершённый продукт требует helper APK с отдельным UID в настоящем TUN,
контроль невыбранного приложения и физические app scenarios. Доступность
устройства не предполагается; pending gates описываются в
[test-plan.md](test-plan.md). Числа ниже — целевые SLO, утверждённые после
baseline P00; они ещё не являются измеренными показателями продукта.
